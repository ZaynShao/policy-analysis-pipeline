## 背景

pipeline(L1 采集)会把"机器拿不准"的源质量项推到衡观让人判,判完结论回灌 pipeline。

- **谁用**:MANAGER 角色(builder/技术性判断,非一线运营)。
- **你建什么**:一张 PG 表 + 一个 NestJS 模块 + 一个 Vue 页。pipeline 侧(信封 / 传输 / 回灌)已建好,你只管"人在衡观上怎么看、怎么判、写哪几个字段"。
- **数据流(你在中间这段)**:
  `pipeline sync 脚本 → upsert 进你这张表(待判项)→ 你的页列出来 + DeepSeek 讲人话 → 人判 → 你写 verdict 字段 → pipeline poll 脚本读走回灌 + 置 syncedBack`

## 1. Prisma 表 `L1ReviewQueue`

```prisma
enum L1ReviewKind { gate checkpoint sweep fetch_fail }

model L1ReviewQueue {
  id              String       @id @default(cuid())

  // —— pipeline sync 写入,人只读 ——
  dedupeKey       String       @unique          // "{kind}::{ref}"
  pipelineKind    L1ReviewKind
  pipelineRef     String                        // channel / pid / url
  reason          String?                       // 为何进池
  suggestedAction String?                       // 机器建议(= 某个 verdict)
  confidence      Float?
  evidence        String?                       // 标题 / 正文片段 / probe 结果
  channel         String?
  runLabel        String?

  // —— DeepSeek 叙述,你后端写 ——
  aiNarration     String?
  aiNarratedAt    DateTime?

  // —— 人审写入(PATCH verdict)——
  verdict         String?                       // null=待判;须 ∈ 该 kind 的 VERDICTS
  corrections     Json?                         // 可选:{corrected_label} 或 {retry_params}
  reviewer        String?                       // 判定人(req.user)
  note            String?
  verdictAt       DateTime?

  // —— pipeline poll 写入,你别动 ——
  syncedBack      Boolean      @default(false)
  createdAt       DateTime     @default(now())

  @@index([verdict])
  @@index([pipelineKind])
}
```

## 2. VERDICTS(每 kind 允许的裁决 · 前后端对齐 · 与 pipeline `review_pool.VERDICTS` 一致)

| kind | 允许的 verdict | 含义(展示给人) |
|---|---|---|
| `gate` | `pass` / `commentary` / `reject` | 这条该当政策收 / 该当评论收 / 弃 |
| `checkpoint` | `promote` / `drop` | 这个候选渠道提升去验证 / 移除 |
| `sweep` | `confirm` / `keep` | 确认是误分类(将挪走)/ 不动 |
| `fetch_fail` | `retry` / `unfetchable` / `drop` | 换参数重抓 / 标记抓不了 / 跳过 |

## 3. 端点(NestJS 模块 `l1-review`,`JwtAuthGuard` + 服务内 `req.user.role==='MANAGER'`)

- `GET /l1-review?kind=&pending=true` — 列待判项(`verdict IS NULL`),可按 kind 过滤。
- `POST /l1-review/:id/narrate` — 调 `DeepseekService` 生成 `aiNarration`(温度 0.3,JSON mode),写 `aiNarration`/`aiNarratedAt` 返回。
- `PATCH /l1-review/:id/verdict` — body `{ verdict, note?, corrections? }`;**校验 `verdict ∈ 该行 pipelineKind 的 VERDICTS`**;写 `verdict`/`reviewer`(= `req.user`)/`note`/`corrections`/`verdictAt=now()`。

## 4. Vue 页 `views/quality/L1ReviewQueue.vue`(+ `api/l1Review.ts` + router + nav,均 `role==='MANAGER'` 可见)

卡片列每条待判项:

- **顶部:AI 叙述**(`aiNarration`,人话)——进页时若为空先调 `/narrate` 生成。
- **下方:真证据折叠区**——原样展示 `pipelineRef` / `reason` / `evidence` / `suggestedAction` / `confidence`(**不可被叙述替代**)。
- **底部:verdict 下拉**(按该行 kind 给选项 + 含义)+ `note` 输入 + 可选 `corrections`(fetch_fail 给 `retry_params`,gate 给 `corrected_label`)+ 提交。
- 提交后从待判列表移除、刷新。

## 5. DeepSeek 叙述 prompt(后端 `/narrate` 用)

```
system: 你是数据质量助理,给技术审阅人把一条"机器拿不准的源质量项"讲成人话。
        只解释、不替人做判断;不得编造证据外的信息。

user: 这是一条进入人工审核池的项,kind={pipelineKind}。
      - 它指向:{pipelineRef}
      - 机器为何拿不准(reason):{reason}
      - 证据(evidence):{evidence}
      - 机器倾向(suggested_action):{suggestedAction},置信:{confidence}
      请输出 JSON:{"narration": "<=120字,说清三件事:这是什么、为什么进池、
                   审阅人要在哪几个选项里判(列出该 kind 的 verdict 及含义)>"}
```

(该 kind 的 verdict 选项含义见 §2,拼进 prompt。)

## 6. 护栏(必须守)

- **LLM 只帮人看懂,不替判、不进回灌**:真证据(`reason`/`evidence`/`pipelineRef` 原值)必须与叙述并列,人对着真东西拍板。
- **只写人审 5 字段**(`verdict`/`reviewer`/`note`/`corrections`/`verdictAt`);**别动** pipeline 写的字段;**别置 `syncedBack`**(那是 pipeline poll 的)。
- `verdict` 必须 ∈ 该行 kind 的 VERDICTS,后端强校验。
