L1 省级能源政策覆盖缺口

漏因诊断 + 统一补采机制设计 · 2026-06-15 · 触发:2026-05 能源月刊交叉核对发现 3 条省级能源政策 ABSENT

一句话结论：这 3 条政策不是被关键词或相关性过滤误杀，而是它们的发文渠道根本没被扫描。 渠道层有两类硬伤：(1) 渠道生命周期没有闭环——发现是手动 oneshot、验证是单次首探、候选→验证晋升是写死的一次性快照， 常驻增量只扫已验证渠道，于是首探失败的渠道永久变暗；(2) 省级能源局从未升为一等发现目标（31 省验证过的能源局 = 0）， 国家能源局派出监管机构（发电力市场细则的那一类）整个没建模。

三层机制根因（从主到次）

A渠道生命周期没有闭环 —— 主因

  • 发现是手动 oneshot（scripts/_oneshot/expand_channels_l1.py），不在任何 cron。
  • 验证是单次首探：channel_discovery.py 仅 probe.verdict=="ok" 才置"验证"，否则落"候选"。 政府站首探失败是常态（JS 空壳、GBK、403、猜错的 list_url）。
  • 候选→验证晋升无常驻机制：promote_checkpoint_channels.py 是写死的 8 个商务/市监域名快照（手工核过那一次），不是循环。
  • 常驻增量 run_incremental.py 只扫 status=验证。

→ 验证前沿冻结在 ~165 条，首探失败的渠道永久变暗。量化后果： 919 渠道里 754 是候选；31 个省，验证过的省级能源局 = 0（仅 3 条"能源局 验证"是福州/南昌的市级模板首页，非真实列表页）。 山东光伏、吉林新能源就死在这里——渠道明明在表里，只差一次复探/晋升。

B省级能源局冷启动循环依赖

province_targets_from_registry 只有当 registry 里该省已有"能源"机构条目时，才生成能源局目标。 而 registry 里"能源"条目只有 3 条（内蒙古能源局 + 2×国家能源局）。 要先采到能源政策才能发现能源渠道——死循环。商务/市监走 commerce_market_targets 无条件 31 省铺开，能源局没这待遇。 （旁证：真实域名 nyj.shandong.gov.cn 甚至被误标成 channel_type: 政府网，说明省能源局根本没被当一等目标生成。）

CNEA 派出监管机构没建模 —— 山西案专属根因

国家能源局有派出机构（6 区域监管局 + ~30 省监管办），它们发电力中长期 / 现货 / 并网 / 辅助服务细则， 域名在 nea.gov.cn 族、不在省 gov.cn。NATIONAL_TARGETS 只有 www.nea.gov.cn， 没有任何 channel_type / 目标生成器 / 域名匹配支持这一类。这是电力交易业务线一整条高价值供给被结构性漏掉，山西细则只是其中一例。

统一补采机制（补三层，不补 3 条）

原则延续本仓"统一机制修复、不打补丁"：让任一省级能源局 + 任一 NEA 监管机构成为常态可采，且首探失败能自愈。

① 闭合渠道生命周期（治 A，主修）：新增常驻"候选自愈复探 + 自动晋升"步骤。 对候选渠道重跑 discover_one（已自带 firecrawl 渲染兜底 + Tavily/LLM 重找真实列表页 + 机构核验）； probe ok 且机构核验过 → 自动晋升验证、进扫描；机构核验有歧义 → 留候选 + 写 review pool 交人（B14）。 首跑即把 754 候选全量自愈（一次性回收山东/吉林），此后稳态保鲜。
② 省级能源局升一等目标（治 B）：仿 commerce_market_targets，无条件给 31 省生成 发改委+能源局 目标， 域名交给发现解析，绕开 registry 冷启动循环。
③ NEA 派出监管机构建模（治 C）：新增 能源监管 channel_type + 6 区域监管局/省监管办目标生成器， 扩 _institution_match 让 nea.gov.cn 子域绑定；同步在 00 背景资料/渠道目录.md 立这一段。

落点：scripts/l1_collect/channel_discovery.py（目标生成）、新 channel_reprobe.py（复探晋升）、 scripts/_oneshot/expand_channels_l1.py（接新 level）、00 背景资料/渠道目录.md（NEA 段）。 自动晋升的安全性由下游兜底：扫描仍按关键词过标题、policy_gate 仍逐篇 LLM 判类，错渠道只会少命中、不会灌脏数据入库。
