2. 架构

β 接口:消费 wewe-rss 的 HTTP JSON feed(非直读其 SQLite),wewe-rss 用 FEED_MODE=fulltext 自带全文并扛微信反爬;feed 全文不足时入库脚本 trafilatura 兜底抓 mp.weixin 原页(限速)。

分层纪律:L1 只做确定性结构性处理(去重 / 招聘·节日·视频丢弃 / market_intel 结构路由 / 失败壳页质量门),不含任何 LLM、不写 LLM 判定字段;相关性/主题判断留 L2(commentary_signals)。

微信公众号(国内 IP, 用 token)
  └─ wewe-rss discovery ─HTTP JSON feed(fulltext)─┐
                                                   ▼
  入库脚本: 拉feed→去重(vault+台账)→结构性过滤→全文/兜底→写vault(仅追加)→记台账
                                                   ▼
  vault 0_raw/commentaries/*.md  +  state/commentary_ingest/(台账/last_run/market_intel暂存)
  (token失效时: detector→createLoginUrl→QR→openclaw推飞书→轮询getLoginResult→恢复)

4. wewe-rss 运行事实(实测)

镜像
cooderl/wewe-rss-sqlite:latest — Docker Hub 直连被墙,用国内镜像源 docker.1ms.run 拉(daocloud 已 403)
启动参数
-p 4000:4000 -e DATABASE_TYPE=sqlite -e AUTH_CODE=<secret> -e FEED_MODE=fulltext -e ENABLE_CLEAN_HTML=true -v <data>:/app/data
数据卷
SQLite + token 在 /app/data(本机 ~/wewe-rss-data)。表 accounts(status: 0=失效/1=有效/2=禁用)
feed 端点
GET /feeds/all.json?limit=N,鉴权 Authorization: Bearer <AUTH_CODE>
tRPC 端点
/trpc/*,鉴权 Authorization: <AUTH_CODE>(裸 code,无 Bearer — 两种头别混)
feed 结构
JSON Feed v1;item 字段 id / content_html / url / title / image / date_modified / author。日期是 date_modified(非标准 date_published);author 单数对象;id 即微信短链 hash(22 位)
limit 陷阱(已硬化):/feeds/all.json 不带 limit 默认只回 30 条/次(实测)。15 号合并、忙时 6h 内常 >30 → 静默漏。生产 feed-url 必须显式给大 limit(如 400);代码不硬编码 limit;coverage_warning(本轮与已见零重叠)是兜底信号。

token 失效 → 扫码恢复流程(tRPC,无 superjson,响应 {"result":{"data":...}})

① POST /trpc/platform.createLoginUrl   body {}   → {uuid, scanUrl:"https://open.weixin.qq.com/connect/confirm?uuid=..."}
② scanUrl 渲染成二维码 → openclaw 推飞书
③ GET  /trpc/platform.getLoginResult?input={"id":"<uuid>"}   轮询直到登录成功
④ 确认: token_health.check_token(db).valid 持续为 True
实测坑:UI 里把账号 toggle 成"启用" ≠ token 真活。旧 token 一旦被真用即被微信打回 status=0;只有真扫码拿新 token、且 check_token 持续 valid 才算恢复。

6. 触发频率(已敲定 2026-06-08)

节奏频率接线
① wewe-rss discovery(耗 token)每天 1 次 @07:00wewe-rss CRON_EXPRESSION="0 0 7 * * *"(6 字段:秒分时日月周)
② ingest(feed→vault)每天 1 次 @07:30host cron 30 7 * * * → run --feed-url '...?limit=400' ...
③ token 检测 → 推 QR(免费,只读 sqlite)每 6hhost cron 0 */6 * * * → run --check-token --db-path ...
⚠️ 防重推(部署须接):token 检测 6h/次,若失效且用户尚未扫码,会重复触发 QR 推送刷屏。relay 须加"恢复会话进行中则不重推"幂等保护(Codex relay 接生产触发时一并做)。
