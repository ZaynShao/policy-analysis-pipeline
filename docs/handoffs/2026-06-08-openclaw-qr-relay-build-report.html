核心流程

  1. 调用 token detector 判断 wewe-rss token 是否有效。
  2. 无效时调用 POST /trpc/platform.createLoginUrl 获取 uuid 和 scanUrl。
  3. 将 scanUrl 渲染为 QR PNG。
  4. 通过 OpenClaw adapter 推送二维码图片和说明文案到 IM。
  5. 轮询 GET /trpc/platform.getLoginResult?input=...。
  6. 扫码成功后再次执行 token health 确认。
  7. 向 IM 发送成功、健康未恢复或超时通知。
  8. OpenClaw 不可达或扫码超时，走现有 alert seam / oc-ctl notify fallback。

wewe-rss 接口事实

动作端点鉴权载荷/响应
创建登录 URL POST /trpc/platform.createLoginUrl 裸 Authorization: <AUTH_CODE> body {}，读取 result.data.uuid 和 result.data.scanUrl
轮询登录结果 GET /trpc/platform.getLoginResult?input=... 裸 Authorization: <AUTH_CODE> input 为 URL encoded {"id":"uuid"}
feed 健康验证 /feeds/all.atom 等 Authorization: Bearer <AUTH_CODE> 演练后返回 HTTP 200

生产接入建议

  1. 在主 session 把 relay_once 接到现有 token_health.check_token / run.py --check-token 触发点。
  2. 凭据只走环境变量、OpenClaw 本地配置或凭据文件，不进 git。
  3. 优先使用 Feishu channel；WeChat channel 当前只作为次级路径，因为图片投递曾不稳定。
  4. 部署保持本地或国内节点，避免微信读书账号触发地理风控。
  5. 后续真实演练不要靠长期保持 DB status=0，避免最终健康检查假阴性。
