1. 现象

2. 结论（先行）

根因：部署配置缺失，非数据缺失、非代码缺陷。知识库同步服务（KnowledgeSyncService）设计为直接读取 vault 文件目录，目录位置由环境变量 KNOWLEDGE_VAULT_DIR 指定；当前 heng-backend 容器既未配置该环境变量、也未挂载 vault 目录，服务启动时按设计自我停用（日志有明确 WARN），知识库三张数据表为空，视图因此无料可显。
修复方案已经过一次临时接通实测：挂载 vault（只读）+ 配置环境变量后，手动触发同步 4 秒成功，产出 1184 条目 / 1649 关系 / 13 主题，与上游产物数量逐项吻合。验证完成后已将环境完整回退（配置、挂载、数据表均恢复原始状态），等待按正式发布流程落地。

3. 数据链路全景与断点定位

①政策情报管线（policy-pipeline，VPS cron）每日生产 L1/L2 产物，经白名单机制提交至 vault 仓（服务器本地路径 /root/policy-vault）正常
②投影通道：run_sync 将 vault 产物投影至 heng-pg（Policy / PolicySemanticRelation / CommentarySignal 等表），供衡观既有视图消费正常
③知识库同步通道（新增）：KnowledgeSyncService 按 cron（每日 11:30）读取 KNOWLEDGE_VAULT_DIR 指向的 vault 目录，经 vault-parser 解析后写入 KnowledgeEntry / KnowledgeRelation / KnowledgeTheme 表断点
④政策知识库 / 政策图谱 / 速览卡视图读取上述三张表渲染表空 → 无显示

5. 已验证的修复方案（待按正式流程实施）

改动集中在部署编排一处（safety-platform 仓的 docker-compose，heng-backend 服务块），共两行：

services:
  heng-backend:
    environment:
      KNOWLEDGE_VAULT_DIR: /vault-mirror        # ← 新增
    volumes:
      - /root/policy-vault:/vault-mirror:ro     # ← 新增（务必只读）

随后重建 heng-backend 容器即可。生效路径：启动日志出现 知识库定时同步已注册: 0 30 11 * * * Asia/Shanghai；首次数据可等每日 11:30 定时同步，或经 POST /api/v1/knowledge/sync/run 手动触发（需 MANAGER 角色）。

6. 时序与运行约束

时刻（CST）环节说明
02:00 / 03:00 / 03:30夜间产线：关系增量 → 信号链 → 上下文链共持一把锁串行，失败各自告警
