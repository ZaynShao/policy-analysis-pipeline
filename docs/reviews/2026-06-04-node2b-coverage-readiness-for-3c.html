核心判断

当前②-B不够支撑全量③-C。原因不是小样本质量没有闭环,而是覆盖面太小:当前资料库只有50个新流程 business_view,相对935个 tracked raw 政策只覆盖约5.3%。

③-C的 derives_from、aligns_with、extends、iterates 依赖稳定 theme/region/business_view。现在全量启动会把大量未归属政策排除或误连。

对③-C的含义

关系类型现在能否全量跑原因
derives_from不建议地方承接上级政策需要双方都有稳定主题和地区层级,当前覆盖太少。
aligns_with不能同主题跨地区对齐需要足够主题簇,50个样本不足。
extends不建议范围扩展需要前后政策链和地区/对象范围,当前容易漏链。
iterates可小样本验证同机构同主题年度续作可在已覆盖样本内做机制验证,但不能声称全量。

推荐下一步

推荐路径:继续②-B覆盖,不要进④,也不要全量③-C。

下一步应做一个②-B扩展 dry-run:优先选择与③-B高精度关系相连、且处于 power_market / charging_infra / vpp / v2g / energy_storage 等高价值主题附近的政策,形成下一批覆盖样本。这样既服务③-C,也控制模型成本。

可接受的小范围③-C例外

如果需要先验证③-C机制,只能选一个明确子集,例如“当前50个 business_view 内部 + 已有③-B关系相连的政策”。该子集只能输出 preview,不能 apply,也不能作为④实质消费依据。

原则确认

  • 本审计只读 state 和 vault 派生层,不写 vault。
  • 没有调用模型。
  • 没有生成③-C关系。
  • 没有消费人工池或 blocked signals。
  • 结论是覆盖面判断,不是业务关系判断。
