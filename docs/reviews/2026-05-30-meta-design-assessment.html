3.2 结晶页：恰恰证明"按需合成"才是强项

我读了 themes/GREEN_POWER_TRADING_THEME/overview.md——它非常好：政策谱系准确、子领域划分清晰、领域判断到位。但请注意三件事：

  • 它是 last_updated: 2026-04-28 的快照，policies_count: 45 写死在 frontmatter 里——新政策进来它就过期；
  • 它是 LLM 一次性合成的产物，不是确定性派生；
  • 13 个主题 × ~5 文件 = 60 个这样的快照，都在静默老化。

这正是论点：结晶页好，说明 LLM-over-语料的合成 是你最强的能力——这是支持"按需生成"的证据，不是支持"管道持久化"的证据。一个能写出这种综述的 agent，在你查询时现做一份只会更新、更贴合当下问题。

3.3 五个横向 bug 都指向同一根因

实测报告列的 5 个横向问题——from==to 自环、L1 混入新闻稿、id issuer 错标、doc_num 多匹配错连、关系类型语义糊——不是孤立 bug，是同一个范式压力的症状：用确定性 + 启发式管道，去抽一种本质上抗拒被确定性抽取的材料（中文政策的隐式关系）。修这些 bug 是在给一个方向可疑的引擎打补丁——这正是你说的"修修补补"。

四 · 该留的真资产 vs 该退役的过度物化

✓ 真资产（持久化、是按需产出的底座）

  • L1 语料：999 政策 + 283 评论 + provenance。不可重抓，唯一不可逆资产。
  • canonical 词表：entities / themes / issuers registry。便宜、稳定、消歧必需——检索与一致性的脚手架。
  • 分析框架（皇冠珠宝）：月报原型 + fact-check 规则 + 四维决策框架 + 打分体系 + LESSONS。这是"分析提示词库"。
  • 504 条高精度确定性边：supersedes / clarifies / cites_basis。
  • 确定性身份/元数据：date / region / issuer / 文号。
  • 双仓 + SCHEMA 契约 + 反污染纪律：组织纪律，保留。

✕ 过度物化（从"持久产物"降为"按需/可缓存"）

  • 905 条 LLM 推断边（derives_from / aligns_with / extends，20–40%）：停止当事实持久化。需要时让 agent 现读现判。
  • 60 个结晶页快照：从"管道维护"改为"查询时生成 / 长缓存 + 失效重建"。
  • 721 反链页：仅对高精度边保留有意义；基于 65% 图的反链页会误导 Obsidian graph view。
  • T1 市级 330 城广度推进：对决策层多为噪声。reviewer brief 自己已把它列为"最该被推翻的决策"。
  • 956 business_view 全量重跑焦虑：评分本身有价值（保留为索引/过滤），但别再围绕"全量重跑"组织工作。
  • git 里的数据 + archive churn：数据移出 git LFS 或不入 git；瘦身历史。

关键心智转变："派生层"从"必须预先算全、算准、长期维护的真理"，变成"agent 在查询时按需生成、用完即缓存的视图"。持久化的只有①②③这些稳定、便宜、不会因模型升级而过期的东西。一切"会过期 / 精度存疑 / 模型一升级就该重跑"的 LLM 产物，都不再是"库的状态"，而是"产出的副本"。

这同时解决了你的"修修补补"痛感：你之所以一直在补补，是因为你在维护一个"必须保持新鲜与准确"的重型派生层——而它天然会随每篇新政策、每次模型升级而失效。一旦派生层变成"按需生成"，就没有"维护图谱新鲜度"这件永远做不完的事了。库只维护①②③，它们本就稳定。
