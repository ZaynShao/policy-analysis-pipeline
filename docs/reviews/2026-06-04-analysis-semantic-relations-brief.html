③-C 正确机制

候选生成

  • 读取②归属、③-B、标题、正文窗口
  • 只生成候选
  • 不等于 accepted
→

受限判定

  • MiniMax/DeepSeek 可接入
  • 只判候选
  • 输出 accept/reject/manual_review
→

程序门

  • schema 校验
  • 证据门
  • 人工池阻断
→

preview/apply

  • 先 preview
  • accepted 才能进入③-E v2
  • apply 另行批准

为什么依赖②-B

语义关系不是简单文号命中。它依赖同主题、地区层级、发文主体层级和业务归属。如果②-B没有足够覆盖,③-C会把错误归属连成错误关系。

下一步顺序

  1. 确认本机制说明。
  2. 继续②-B覆盖,或批准一个明确主题/区域子集。
  3. 做③-C preview,只产出候选、accepted、人工池和中文报告。
  4. 生成③-E v2,只消费 accepted 语义关系。
  5. 再进入④实质消费层 preview。
